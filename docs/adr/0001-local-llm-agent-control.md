# ADR 0001: 로컬 LLM(GPU 서버) 에이전트 관제 확장

- 상태: 승인, 구현 완료 (2026-11-23, 실제 환경 검증 전)
  - 구현: D1 로컬 에이전트 job(관리자 승인, 사람·스케줄 실행), D2 gateway 쪽(`local` provider, mTLS, 정책에 GPU 서버 주소가 있으면 거부), D3 가드레일(규칙 기반, fail-closed), D4 break-glass, D5 본문 감사
  - 추가 구현: D2 네트워크·SSH 강제 설정(`infra/gpu/network/`, 적용은 인프라팀), G-6 가중치·이미지 서명 검증(`infra/gpu/signing/`), 본문 보존 90일과 파기·법적 보존(Policy API), 로컬 에이전트 실행 파일과 샌드박스 이미지(`local-agent/`)
  - 결정 (2026-11-23): 본문 보존 기간 90일, break-glass는 관리자 1인 유지, 서명 검증 실패는 break-glass로 해제할 수 없음

### D1 구현 결정 (2026-11-23)
- 로컬 에이전트는 **관리자가 승인한 job**으로만 실행합니다. 등록자 본인은 승인할 수 없습니다. job은 바꿀 수 없으므로, 내용이 바뀌면 새 job으로 등록해 다시 승인받아야 합니다.
- **실행 방법은 두 가지입니다.** 사람(소유자나 관리자)이 직접 실행하거나 스케줄이 실행합니다. 스케줄 주기는 분 단위 간격으로 정하고 최소 15분입니다. 실행해도 되는 때인지는 Policy API가 판정합니다.
- 스케줄 실행의 세션 주체는 `job:<id>`, 사람이 실행하면 그 사람입니다. job마다 동시에 하나만 실행할 수 있습니다.
- 세션 수명은 job의 최대 실행 시간에 여유 5분을 더한 만큼으로 제한합니다. 실행이 끝나면 샌드박스를 삭제하고 세션을 종료합니다.
- 날짜: 2026-11-20
- 관련 문서: [overview.md](../overview.md), [architecture.md](../architecture.md), [threat-model.md](../threat-model.md)

## 1. 배경

지금 플랫폼은 외부 SaaS 모델(Anthropic, OpenAI)을 쓰는 개발자 에이전트를 관제합니다. 이번에 사내 GPU 서버에서 자체 LLM을 서빙하고, 그 LLM이 **로컬 에이전트로 동작**하도록 확장합니다. 로컬 에이전트는 도구를 호출하고 외부로 통신합니다. 그래서 다음 두 가지가 바뀝니다.

- 모델이 외부의 목적지가 아니라 **우리 쪽 공격 표면**이 됩니다. 추론 서버, 가중치, GPU 노드가 여기에 들어갑니다.
- 위협 모델의 잔여위험 #4(자체 호스팅 모델 엔드포인트)는 더 이상 잔여위험이 아닙니다. **막아야 하는 경로**입니다.

### 관제 대상 (주체)

| 주체 | 설명 |
|---|---|
| 개발자 | 기존과 같습니다. `tether` → 오케스트레이터 → OpenShell 샌드박스 안의 Claude Code/Codex |
| 로컬 LLM 에이전트 | GPU 서버에서 서빙하는 자체 모델로 동작하는 에이전트입니다. 도구 호출과 egress가 있습니다 |

ML 엔지니어가 GPU를 직접 쓰는 작업(학습, 평가)은 이번 범위에 넣지 않습니다.

## 2. 결정

### D1. 로컬 LLM 에이전트도 OpenShell 샌드박스 안에서만 실행한다
로컬 에이전트는 개발자 에이전트와 **같은 불변식**을 따릅니다. 에이전트 런타임(도구 실행, 파일시스템, 네트워크)은 OpenShell 샌드박스에서만 실행하고, 세션은 Policy API가 발급하며, 킬 스위치로 회수할 수 있어야 합니다.

- 에이전트 런타임과 추론 서버를 **분리**합니다. 샌드박스는 추론 서버를 직접 부르지 않고 llm-gateway만 부릅니다.
- 세션을 만드는 주체가 사람이 아닐 수 있습니다(예약 작업, 서비스 트리거). 이때 Policy API는 **서비스 주체(workload identity)** 로 세션을 발급하고, 감사 로그의 actor에 서비스 주체와 트리거한 사람을 함께 남깁니다.

### D2. 추론 서버는 llm-gateway에서 오는 요청만 받는다 (네트워크 강제)
GPU 서버 네트워크는 우리 팀이 강제합니다.

- vLLM/TGI/Triton 같은 서빙 엔진은 **llm-gateway에서 오는 mTLS 연결만** 받습니다. 방화벽이나 NetworkPolicy로 다른 출발지는 모두 거부합니다.
- 서빙 엔진의 관리 포트(metrics, admin)는 관제 네트워크에만 엽니다.
- llm-gateway에 `local` provider를 추가합니다. 기존 `/{provider}/{path}` 라우팅을 확장하고, OpenAI 호환 API를 씁니다. 모델 허용 목록, 분당 요청 수, 세션 확인은 기존 경로를 그대로 재사용합니다.
- GPU 서버의 SSH 접근은 관리자 그룹과 bastion으로만 허용하고, 감사 대상으로 둡니다.

### D3. 가드레일은 llm-gateway에서 인라인으로 실행하고, 기본 동작은 fail-closed다
- 입력 가드레일(프롬프트 인젝션, 민감정보, 금지 주제)과 출력 가드레일(민감정보 유출, 위험한 도구 호출 지시)을 gateway의 요청·응답 경로에 둡니다. 외부 provider와 local provider에 **모두** 적용합니다.
- 어떤 가드레일 규칙을 적용할지는 GitOps 정책에 둡니다. 정책 번들 서명, 버전, `POLICY_SUPERSEDED` 같은 기존 메커니즘을 그대로 씁니다.
- 스트리밍 응답은 청크 단위로 검사합니다. 위반이 나오면 스트림을 끊고 차단 이벤트를 기록합니다.
- 가드레일이 timeout이나 오류를 내면 **요청을 거부합니다(fail-closed)**. interceptor와 같은 원칙입니다.

### D4. 가드레일 장애 시 관리자 break-glass 해제
가드레일 장애로 서비스가 멈추면, 관리자가 가드레일을 일시적으로 해제할 수 있습니다. 해제는 **통제된 예외**로만 허용합니다.

- **권한:** `ADMIN_GROUPS` 소속만 해제할 수 있습니다. 2인 승인을 권장합니다(아래 열린 질문 참고).
- **범위:** 범위를 반드시 지정합니다. 전체, 정책, 모델, 세션 중 하나입니다. "전부 영구 해제"는 허용하지 않습니다.
- **기간:** TTL을 필수로 둡니다(예: 최대 4시간). 기간이 끝나면 자동으로 fail-closed로 복귀합니다.
- **감사:** 해제와 복귀 모두 OCSF 이벤트로 남깁니다(`guardrail.bypass.start`, `guardrail.bypass.end`). 해제 중에 처리된 요청 이벤트에는 `guardrail_bypassed: true`를 표시합니다.
- **경보:** 해제가 시작되면 SIEM과 보안팀에 즉시 경보를 보냅니다.
- **유지되는 것:** 해제하더라도 세션 검증, 모델 허용 목록, 네트워크 정책, 프롬프트·응답 감사(D5)는 **해제되지 않습니다**.

### D5. 프롬프트와 응답은 항상 감사에 남긴다
기존 방침인 "`llm.request`는 사용량만 기록하고 프롬프트는 제외"를 **폐기합니다**. 개발자 에이전트와 로컬 LLM 에이전트 모두에 적용합니다.

- 새 이벤트 `llm.content`를 추가합니다. 프롬프트, 응답, 도구 호출을 session_id와 request_id로 `llm.request`에 연결합니다.
- 본문이 크고 민감하므로 OCSF 메타데이터와 **분리해 저장**합니다. 본문은 암호화된 별도 저장소에 두고, 감사 이벤트에는 참조와 해시만 남깁니다.
- 본문 조회 권한은 보안 관리자로만 제한합니다. 조회 행위 자체도 감사합니다(`audit.content.read`).
- 보존 기간과 파기 정책을 정합니다.
- 저장에 실패하면 요청을 거부합니다(fail-closed). 감사 없는 추론을 허용하지 않기 위해서입니다.

## 3. 신뢰 경계

```text
 개발자 Mac                   컨트롤 플레인                         데이터 플레인 (OpenShell gateway)
┌──────────────┐  launch  ┌──────────────┐ 세션  ┌────────────┐
│ tether│─────────►│ Orchestrator │──────►│ Policy API │◄── CI (서명 정책 번들: 네트워크·가드레일·모델)
└──────────────┘          │              │       └─────┬──────┘
┌──────────────┐ trigger  │              │             │ 세션·정책 조회
│ 서비스 트리거  │─────────►│ (workload ID)│             │
└──────────────┘          └──────┬───────┘             │
                                 │ openshell            │
                    ┌────────────▼────────────────┐    │
                    │ Sandbox: 개발자 에이전트       │    │
                    │ Sandbox: 로컬 LLM 에이전트     │────┼──► GitHub(org 경로) / 레지스트리(RO) / 허용 도구 host
                    └────────────┬────────────────┘    │
                    ═════════════╪══════════ 신뢰 경계 A: 샌드박스 → gateway (세션 토큰, egress IP)
                                 ▼                      │
                    ┌─────────────────────────────┐    │
                    │ LLM Gateway                 │◄───┘
                    │  ├ 세션·모델·rate 검사        │
                    │  ├ 가드레일 (fail-closed,    │──► 감사: llm.request(OCSF) + llm.content(암호화 저장소)
                    │  │   break-glass TTL 해제)   │
                    │  └ provider 라우팅           │──► Anthropic / OpenAI (회사 키)
                    └────────────┬────────────────┘
                    ═════════════╪══════════ 신뢰 경계 B: gateway → GPU (mTLS, 출발지 고정)
                                 ▼
                    ┌─────────────────────────────┐
                    │ GPU 서버                     │
                    │  추론 서버(vLLM 등)            │  ← 다른 출발지는 네트워크에서 거부
                    │  서명된 가중치 / 이미지         │  ← SSH는 bastion + 관리자만
                    └─────────────────────────────┘
```

| 경로 | 강제 지점 |
|---|---|
| 노트북 → 추론 서버 직접 호출 | 신뢰 경계 B: 네트워크와 mTLS |
| 샌드박스 → 추론 서버 직접 호출 | OpenShell L7 정책(GPU host는 허용 목록에 넣지 않음, 컴파일러가 거부) + 신뢰 경계 B |
| 로컬 에이전트 → 임의 외부 host | OpenShell L7 정책 |
| 가드레일 우회 | gateway 단일 경로. 해제는 break-glass로만 가능 |
| 감사 회피 | 감사를 저장하지 못하면 추론을 거부 |
| 변조된 가중치나 이미지 | 서명 검증 후 로드 (G-6) |

## 4. 결과와 영향

### 기존 코드 변경
| 구성요소 | 변경 |
|---|---|
| `services/llm-gateway` | `local` provider, 가드레일 파이프라인(요청·스트림), `llm.content` 기록, break-glass 상태 조회 |
| `services/policy-compiler` | 정책 스키마에 `llm.local`(모델, 엔드포인트)과 `guardrails` 섹션 추가. GPU 추론 host를 `network.allow`에 넣으면 거부 |
| `services/policy-api` | 서비스 주체 세션, break-glass API(`POST/DELETE /v1/admin/guardrails/bypass`), `llm.content` 저장·조회, 마이그레이션 |
| `services/sandbox-orchestrator` | 서비스 트리거로 로컬 에이전트 샌드박스 실행, 킬 스위치 대상 확장 |
| `docs/threat-model.md` | 잔여위험 #4 제거, 신규 우회 경로 항목 추가 |
| `docs/incident-response.md` | break-glass 절차, `llm.content` 조사 절차 추가 |

### 트레이드오프
- **지연:** 인라인 가드레일 때문에 TTFT가 늘어납니다. 가드레일 모델을 추론과 같은 GPU에 둘지는 용량 계획에서 결정합니다.
- **개인정보:** 프롬프트를 전부 저장하면 개발자 입력에 들어간 개인정보와 비밀값이 함께 저장됩니다. 구성원 고지, 보존 기간, 접근 통제를 법무·개인정보 담당과 확정해야 합니다.
- **break-glass 남용:** 해제는 곧 가드레일 공백입니다. TTL, 범위, 경보, 사후 리뷰로 통제합니다.

## 5. 새 우회 경로 (threat-model 추가 예정)

| # | 우회 | 통제 |
|---|---|---|
| G-1 | 노트북이나 사내망에서 추론 서버 직접 호출 | 네트워크 출발지 제한 + mTLS (D2) |
| G-2 | 샌드박스 정책에 GPU host 추가 | 컴파일러 거부 + interceptor |
| G-3 | 로컬 에이전트가 도구 호출로 데이터 유출 | OpenShell L7 정책, 출력 가드레일, `llm.content` 감사 |
| G-4 | 가드레일 장애를 유도해 우회 | fail-closed, 해제는 관리자 break-glass(TTL, 경보)로만 |
| G-5 | break-glass 장기화나 남용 | TTL 강제, 범위 지정, 2인 승인(검토 중), SIEM 탐지 규칙 |
| G-6 | 변조된 가중치나 이미지 로드 (pickle RCE 포함) | 서명된 가중치(safetensors만 허용), 이미지 서명 검증 |
| G-7 | GPU 서버 SSH로 서빙 설정 변경 | bastion + 관리자만, 감사 |

## 6. 첫 작업 순서

1. **Staging 구성:** 실제 OpenShell gateway와 GPU 노드 1대로 구성합니다. 기존 불변식(M1)과 G-1, G-2 negative test를 함께 검증합니다.
2. **Negative e2e를 merge gate로:** 직접 호출, 토큰 재사용, 세션 회수 후 호출, 가드레일 장애(fail-closed), break-glass TTL 만료를 검증합니다.
3. **llm-gateway `local` provider + 가드레일 인터페이스:** 처음에는 규칙 기반으로 시작하고, 이후 가드레일 모델로 교체할 수 있게 만듭니다.
4. **`llm.content` 저장소와 접근 통제**, 마이그레이션.
5. **break-glass API**와 SIEM 탐지 규칙.
6. **서비스 주체 세션**과 로컬 에이전트 샌드박스 실행.

## 7. 열린 질문
- break-glass를 관리자 1인이 해제할 수 있나요, 아니면 2인 승인이 필요한가요? 최대 TTL은 얼마인가요?
- `llm.content`의 보존 기간과 저장 위치(사내 오브젝트 스토리지인지 DB인지)는 무엇인가요?
- 가드레일 구현으로 NeMo Guardrails를 쓰나요, 자체 규칙과 분류 모델을 쓰나요? 가드레일 모델은 추론 GPU를 함께 쓰나요?
- 로컬 에이전트 세션을 트리거하는 주체(사람, 스케줄, 서비스)와 각각의 승인 정책은 무엇인가요?
